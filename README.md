# Панель управления ботом мэрии г. Манас

Веб-система, куда попадают все обращения жителей из Telegram-бота: переписка,
фотографии, темы, статусы. Отсюда же ботом управляют — тексты ответов, ключи,
готовые ответы, рассылки.

---

## Коротко: нужно ли запускать обе части?

**Да, это две отдельные программы, и обычно работают обе.**

| | Что это | Без чего не может |
|---|---|---|
| **Панель** — этот репозиторий, [tg-bot_srm](https://github.com/q-werty452/tg-bot_srm) | сайт для сотрудников мэрии | работает сама по себе, но без бота в ней не появятся новые обращения |
| **Бот** — репозиторий [tg_bot-](https://github.com/q-werty452/tg_bot-) | тот, кто говорит с жителями в Telegram | работает и без панели: отвечает жителям, а обращения копит на диске и дошлёт, когда панель включат |

То есть жителей бот не подведёт, даже если панель выключена. Но чтобы отдел
видел обращения и отвечал людям — нужны обе.

**Порядок запуска:** сначала панель, потом бот. Если наоборот — тоже ничего
страшного, бот сам достучится, когда панель поднимется.

---

## Первый запуск: 6 шагов

### 1. Скачать обе части и установить зависимости

```bash
git clone https://github.com/q-werty452/tg-bot_srm.git    # панель
git clone https://github.com/q-werty452/tg_bot-.git       # бот

cd tg-bot_srm
python3 -m venv venv
./venv/bin/pip install -r requirements.txt

cd ../tg_bot-
python3 -m venv .venv
./.venv/bin/pip install -r requirements.txt
cd ../tg-bot_srm
```

Дальше все команды выполняются в папке панели, если не сказано иное.

### 2. Создать файл .env

Скопируй `.env.example` в `.env` и сгенерируй два секрета:

```bash
cp .env.example .env
./venv/bin/python -c "from cryptography.fernet import Fernet; print('SECRETS_KEY =', Fernet.generate_key().decode())"
./venv/bin/python -c "import secrets; print('BOT_API_TOKEN =', secrets.token_urlsafe(32))"
```

Впиши полученные значения в `.env`:

- `SECRETS_KEY` — которым шифруются ключи ИИ и токены ботов в базе.
  **Потеряешь его — панель не сможет расшифровать сохранённые ключи**,
  их придётся вписать заново.
- `BOT_API_TOKEN` — пароль, по которому бот стучится в панель.
  Его же надо вписать боту (шаг 5).

### 3. Создать базу и справочники

```bash
./venv/bin/python manage.py migrate
./venv/bin/python manage.py seed
```

`seed` заводит начальные категории, районы и муниципальные предприятия.
Команду можно запускать повторно — существующее не портится.

### 4. Создать первого сотрудника

```bash
./venv/bin/python manage.py createsuperuser --email admin@meriya.kg
```

Дальше остальных сотрудников заводят прямо в панели, в разделе «Сотрудники».

### 5. Связать с ботом

Открой файл `файл .env Telegram-бота` и впиши туда две строки:

```
CRM_URL=http://127.0.0.1:8000
CRM_BOT_TOKEN=<тот самый BOT_API_TOKEN из .env панели>
```

**Это и есть вся связка.** Токен в двух файлах должен совпадать символ в символ.

### 6. Запустить обе части

Два терминала. В первом — панель:

```bash
cd ~/manas-crm
./venv/bin/python manage.py runserver
```

Во втором — бот:

```bash
cd ~/tg_bot-
.venv/bin/python bot.py
```

Панель открывается на `http://127.0.0.1:8000`.

## Как проверить, что связка работает

1. В логе бота при старте должна быть строка
   `Панель управления: http://127.0.0.1:8000`, а следом успешные запросы
   `health` и `config`.
2. Напиши боту в Telegram любое сообщение.
3. Обнови панель — обращение появится в списке с заголовком и категорией.
4. Открой карточку, включи «Отвечает сотрудник», напиши ответ —
   он придёт жителю в Telegram за пару секунд.

Если обращения не появляются, смотри раздел «Если что-то не работает».

## Что где в панели

| Раздел | Зачем |
|---|---|
| **Обращения** | список со всеми диалогами, поиск и фильтры по статусу, теме, району |
| **Карточка обращения** | переписка, фото, статус, срок, исполнитель, ответ жителю, заметки отдела |
| **Новая заявка** | завести обращение вручную: человек пришёл ногами или позвонил |
| **Настройки бота** | тон ответов, выключатель бота, текст на время техработ, состояние бота |
| **Ключи и токены** | ключи ИИ и токены Telegram: добавить, заменить, проверить, выбрать модель |
| **Готовые ответы** | «вопрос → точный ответ», бот отдаёт их дословно, не тратя модель |
| **Рассылки** | сообщение всем жителям или только одному району |
| **Статистика** | сколько обращений, по каким темам и районам, доля «помогло» |
| **Карта** | обращения точками на карте города |
| **Справочники** | категории со сроками, районы, предприятия, контакты для ответов бота |
| **Сотрудники** | учётные записи и роли |
| **Журнал** | кто что менял и когда |

## Поддерживаемые модели

| Провайдер | Начало ключа | Особенность |
|---|---|---|
| OpenAI | `sk-proj-`, `sk-` | классический GPT |
| Google Gemini | `AIza`, `AQ.` | есть бесплатный тариф с суточным лимитом |
| Anthropic | `sk-ant-` | Claude |
| OpenRouter | `sk-or-v1-` | шлюз: один ключ, модели разных компаний |

Провайдера определять вручную не нужно — панель узнаёт его по ключу сама
(см. следующий раздел).

**Про OpenRouter отдельно.** Это посредник: за одним ключом стоят модели
OpenAI, Google, Anthropic, Meta и других. Имена моделей у него составные,
с указанием владельца: `openai/gpt-4o-mini`, `google/gemini-2.0-flash-exp`.
Значения по умолчанию нет — модель обязательно выбрать в панели, иначе бот
скажет, что не знает, чем отвечать. Удобно тем, что не упираешься в суточный
лимит одного провайдера и можно менять модель, не заводя новых ключей.

---

## Перенос ключей ИИ в панель

Пока ключи лежат в `.env` бота. Чтобы менять их из браузера:

1. Зайди в **Ключи и токены**, добавь ключ провайдера, нажми «Проверить».
2. Панель покажет список доступных этому ключу моделей — выбери нужную.
3. Бот подхватит изменения в течение 30 секунд, перезапускать его не нужно.

После этого строки `OPENAI_API_KEY` и `GOOGLE_API_KEY` в `.env` бота можно
очистить — панель важнее, её значения перекрывают файл.

Токен самого Telegram-бота тоже можно хранить в панели: при его смене бот
сам перезапустит опрос Telegram.

## Ежедневная работа

Запускать надо только две команды из шага 6 — по одной в каждом терминале.
Остановка: `Ctrl+C` в обоих окнах.

Отдельно, по мере надобности:

```bash
./venv/bin/python manage.py geocode   # расставить заявки на карту по адресам
```

Этой команде нужен интернет, и она нетороплива (правило бесплатного
геокодера — не чаще запроса в секунду). Запускай раз в день или руками.

Подробно про карту и геокодер — в разделе «Как работает карта обращений» ниже.

## Как работает карта обращений

Раздел **Карта** показывает обращения точками на карте города: сразу видно
проблемные улицы и где скопились заявки. Работает это в три шага.

**Шаг первый: адрес попадает в заявку.** Житель пишет боту «на Токтогула 45
яма» — ИИ вытаскивает адрес из текста и кладёт в поле «Адрес». Если не
разобрал, сотрудник вписывает адрес руками в карточке. Нет адреса — нет
и точки, но сама заявка живёт как обычно.

**Шаг второй: адрес превращается в координаты.** Это отдельная команда,
она не запускается сама:

```bash
./venv/bin/python manage.py geocode
```

Команда берёт заявки с адресом, но без координат, и спрашивает адреса
у OpenStreetMap. Ей нужен интернет. Она нетороплива — примерно секунда на
адрес: таково правило бесплатного геокодера, чаще стучаться нельзя.
За раз обрабатывает 25 адресов, больше — через `--limit 100`.

Запускать удобно раз в день. На сервере это ставится в cron:

```
0 7 * * *  cd /путь/к/tg-bot_srm && ./venv/bin/python manage.py geocode
```

**Шаг третий: точки на карте.** Страница `/map/` рисует карту OpenStreetMap
и ставит на неё точки. Просроченные заявки — красные, остальные — синие.
По клику открывается номер, тема, статус и ссылка на карточку.

### Что важно знать

**Карта — единственная страница, которой нужен интернет.** Она подгружает
подложку с серверов OpenStreetMap. Без сети остальная панель работает
полностью, а карта покажет пустое поле.

**Найденное не в городе — отбрасывается.** Геокодер по названию улицы легко
находит однофамильца в другом конце страны: «ул. Ленина» первым запуском
нашлась за сотню километров от Манаса. Поэтому поиск ограничен рамкой города,
а результат ещё раз проверяется. Точка за границей города на карту не
попадёт — заявка в чужом районе хуже, чем её отсутствие.
Границы задаются в начале `reports/management/commands/geocode.py`:
константы `CITY_LAT`, `CITY_LON` и `HALF_SIDE`.

**Точность — до улицы, не до дома.** OpenStreetMap знает улицы Манаса лучше,
чем нумерацию домов, поэтому дома 45 и 123 на одной улице могут встать рядом.
Для карты «где болит» этого хватает, для точной адресации — нет.

**Адрес без номера дома обычно не находится** («Центральный парк»). Такие
заявки помечаются как нераспознанные и повторно не запрашиваются, чтобы не
тратить лимит. Впишите в карточке более точный адрес и запустите команду
снова.

## Если что-то не работает

**Обращения не появляются в панели.** Проверь три вещи: панель запущена;
`CRM_URL` в `.env` бота указывает на неё; `CRM_BOT_TOKEN` бота совпадает с
`BOT_API_TOKEN` панели. В логе бота при несовпадении будет
`Панель отклонила POST /tickets/incoming/`.

**Ответ сотрудника не доходит до жителя.** Ответы уходят через очередь, которую
бот разбирает раз в 2–3 секунды. Значит, бот не запущен либо не видит панель —
смотри `bot.log`.

**`Не задан SECRETS_KEY`** — не заполнен `.env` панели, вернись к шагу 2.

**`Не удалось расшифровать секрет`** — `SECRETS_KEY` поменяли после того, как
ключи были сохранены. Впиши старое значение либо задай ключи заново.

**Порт 8000 занят** — запусти на другом:
`./venv/bin/python manage.py runserver 8080` и поправь `CRM_URL` у бота.

**Бот пишет «идут технические работы»** — он выключен в разделе
«Настройки бота», включи галочку обратно.

## Переезд на сервер

1. В `.env` панели: `DEBUG=0`, в `ALLOWED_HOSTS` — домен мэрии.
2. База: SQLite меняется на PostgreSQL правкой блока `DATABASES`
   в `config/settings.py`; код при этом не меняется.
3. Статику собрать: `./venv/bin/python manage.py collectstatic`.
4. Панель запускать через gunicorn за nginx, бота — отдельной службой systemd.
   Файлы жителей из `media/` должен отдавать nginx, а не Django.
5. `CRM_URL` у бота поменять на адрес сервера.
